# 校服平台业务扩展 20 张表说明

对应建表脚本：`20张业务表创建SQL.sql`

## 一、统计口径

本次按 20 张业务表生成建表 SQL：

- 原有修改脚本中已有结构的 16 张表。
- `数据库表分析.md` 中提到但原来没有建表 SQL 的 4 张表：`xfpt_after_sale`、`xfpt_comment`、`xfpt_finance_flow`、`xfpt_withdraw_apply`。

`xfpt_school_message` 是已有学校信息表，本次银行卡账户属于字段扩展，不计入 20 张新增/重建业务表。

## 三、核心业务关系

商品与供应商：

- `xfpt_goods` 存商品主信息。
- `xfpt_goods_size` 存商品尺码、价格、库存。
- `xfpt_school_supplier_rel` 存学校与供应商的合作关系。
- `xfpt_school_supplier_goods_rel` 存合作关系下允许服务的商品。

统购公告与供应商报名：

- `xfpt_group_notice` 存学校发起的统购公告。
- `xfpt_group_notice_item` 存公告下的商品和采购信息。
- `xfpt_supplier_apply` 存供应商针对公告的报名、资质审核、比选结果。

下单、生产、发货：

- `xfpt_cart_item` 存家长购物车。
- `xfpt_order_info` 存订单主表，`order_type` 区分统购和零售。
- `xfpt_order_item` 存订单商品明细。
- `xfpt_production_order` 和 `xfpt_production_order_item` 存生产任务。
- `xfpt_delivery_order` 和 `xfpt_delivery_order_item` 存发货、物流、签收信息。

售后与评价：

- `xfpt_after_sale` 存售后申请、审核、处理、退款结果。
- `xfpt_comment` 存主评价、评分、图片和历史商家回复。
- `xfpt_comment_reply` 存主评价下的单层回复，支持家长和供应商互相回复，不做楼中楼递归。

财务：

- `xfpt_finance_flow` 存订单支付、退款、提现、结算等资金流水。
- `xfpt_withdraw_apply` 存供应商提现申请、审核人、审核结果和打款结果。

## 四、资金流水状态调整

`xfpt_finance_flow.status` 改为三种状态：

- `0`：未支付
- `1`：已到达学校账号
- `2`：已到达供应商账号

资金流水表增加了收款方快照字段：

- `payee_type`：收款方类型，`1` 学校，`2` 供应商。
- `payee_id`：收款方 ID。
- `payee_name`：收款方名称快照。
- `payee_account_name`：收款账户户名快照。
- `payee_bank_name`：收款银行快照。
- `payee_bank_account_no`：收款银行卡号快照。
- `receipt_qr_code`：收款码快照。

这样做的原因是支付发生后，学校或供应商后续即使修改收款资料，也不影响历史流水追溯。

## 五、付费时收款码逻辑

付费时后端应以订单表 `xfpt_order_info.order_type` 为准，不建议让前端自行传收款方。

逻辑规则：

- `order_type = 1`：统购订单
  - 收款方为学校。
  - 弹出学校收款码。
  - 创建资金流水时：`payee_type = 1`，`payee_id = school_id`。
  - 确认到账后：`xfpt_finance_flow.status = 1`。

- `order_type = 2`：零售订单
  - 收款方为供应商。
  - 弹出供应商收款码。
  - 创建资金流水时：`payee_type = 2`，`payee_id = supplier_id`。
  - 确认到账后：`xfpt_finance_flow.status = 2`。

建议流程：

1. 用户点击支付。
2. 后端读取 `xfpt_order_info`。
3. 根据 `order_type` 判断统购或零售。
4. 统购读取学校收款资料，零售读取供应商收款资料。
5. 返回对应收款码给前端弹窗展示。
6. 同时创建 `xfpt_finance_flow`，状态先为 `0` 未支付。
7. 管理端或回调确认到账后，根据收款方改为 `1` 或 `2`。

## 六、收款码来源说明

本次 20 张表中，`xfpt_finance_flow.receipt_qr_code` 保存的是支付时实际展示给用户的收款码快照。

收款码的主数据来源建议：

- 学校收款码：放在学校信息表 `xfpt_school_message`。
- 供应商收款码：放在供应商信息表 `xfpt_supplier_message`。

这两个表是已有基础资料表，不计入本次 20 张业务表。后续如果要完整落库，需要给这两个已有表补充收款码字段，例如：

- `xfpt_school_message.receipt_qr_code`
- `xfpt_supplier_message.receipt_qr_code`

## 七、与学校银行卡字段的关系

学校银行卡账户仍然放在已有表 `xfpt_school_message`：

- `bank_account_name`：银行账户户名
- `bank_name`：开户银行
- `bank_branch_name`：开户支行
- `bank_account_no`：银行卡号

银行卡字段用于学校账户资料维护、转账核对、导出和脱敏展示；收款码用于支付弹窗展示。两者不是同一个字段，不建议混用。

## 八、落库注意事项

建表脚本使用 `CREATE TABLE IF NOT EXISTS`，不会覆盖已有表结构。

如果目标库里已经存在同名旧表，执行脚本不会自动修改旧表字段。需要先确认旧表是否可删除或需要使用 `ALTER TABLE` 迁移。

如要在当前本地 `xfglpt` 库继续落这些表，建议先确认哪些表已存在，再只执行缺失表或单独写迁移脚本，避免影响已有数据。
