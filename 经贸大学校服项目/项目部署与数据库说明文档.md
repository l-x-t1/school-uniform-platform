文档日期：2026-05-04

本文档用于把当前项目迁移到一台新电脑，并说明数据库如何导入、如何继续新增数据库表、如何使用 RuoYi 代码生成器生成对应功能、如何启动后端和前端服务。

## 5. 数据库导入

### 5.1 推荐方式：导入完整业务库和 Nacos 库

当前已经准备了两份完整导出：

| 数据库 | 文件 | 说明 |
| --- | --- | --- |
| `xfglpt` | `D:\xiaofu\数据库导出\xfglpt_full_20260504_191831.sql` | 当前业务库，包含所有表结构、菜单、权限、测试数据，且已修复 `sys_oper_log.OPER_ID` 自增 |
| `xfglpt-nacos` | `D:\xiaofu\数据库导出\xfglpt_nacos_20260504_192617.sql` | 当前 Nacos 配置中心库，包含服务配置 |

如果这两个文件在新电脑路径不同，请把命令里的路径替换成实际路径。

说明：当前仓库中的 `xfglpt_full_20260504_191831.sql` 已修复 `sys_oper_log.OPER_ID` 为 `AUTO_INCREMENT`。如果导入的是旧副本，后续调用 `/operlog` 时会报 `Field 'OPER_ID' doesn't have a default value`。

PowerShell 导入方式：

```powershell
$env:MYSQL_PWD = "123456"

Get-Content -LiteralPath "D:\xiaofu\数据库导出\xfglpt_full_20260504_191831.sql" -Raw |
  & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot --default-character-set=utf8mb4

Get-Content -LiteralPath "D:\xiaofu\数据库导出\xfglpt_nacos_20260504_192617.sql" -Raw |
  & "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot --default-character-set=utf8mb4

Remove-Item Env:\MYSQL_PWD
```

CMD 导入方式：

```cmd
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 < "D:\xiaofu\数据库导出\xfglpt_full_20260504_191831.sql"
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -p --default-character-set=utf8mb4 < "D:\xiaofu\数据库导出\xfglpt_nacos_20260504_192617.sql"
```

导入后验证：

```powershell
$env:MYSQL_PWD = "123456"

& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -N -e "SHOW DATABASES LIKE 'xfglpt%';"
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -N --database=xfglpt -e "SELECT COUNT(*) FROM sys_menu WHERE parent_id = 2333 AND menu_type = 'C';"
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -uroot -N --database=xfglpt -e "SELECT menu_id, menu_name, parent_id FROM sys_menu WHERE menu_name = '新增功能';"

Remove-Item Env:\MYSQL_PWD
```

正常结果：


## 8. 资金流水和收款逻辑

资金流水表：

```text
xfpt_finance_flow
```

状态字段：

```text
status
```

状态含义：

| 值 | 含义 |
| --- | --- |
| `0` | 未支付 |
| `1` | 已到达学校账号 |
| `2` | 已到达供应商账号 |

订单类型字段在订单主表中：

```text
xfpt_order_info.order_type
```

订单类型含义：

| 值 | 含义 | 收款方 | 页面应展示 |
| --- | --- | --- | --- |
| `1` | 统购 | 学校 | 学校收款码、学校银行卡账户 |
| `2` | 零售 | 供应商 | 供应商收款码、供应商收款账户 |

支付逻辑要求：

1. 用户点击付费时，先读取订单 `order_type`。
2. 如果 `order_type = 1`，说明是统购，页面弹出学校收款码或学校银行卡账户。
3. 如果 `order_type = 2`，说明是零售，页面弹出供应商收款码或供应商收款账户。
4. 创建资金流水时，先记为 `status = 0`，表示未支付。
5. 学校确认收到统购款后，把流水改为 `status = 1`。
6. 供应商确认收到零售款后，把流水改为 `status = 2`。

学校收款信息来源：

```text
xfpt_school_message.bank_account_name
xfpt_school_message.bank_name
xfpt_school_message.bank_branch_name
xfpt_school_message.bank_account_no
```

供应商收款信息建议来源：

```text
xfpt_supplier_message
xfpt_withdraw_apply.bank_info_json
```

其中 `xfpt_withdraw_apply.bank_info_json` 是银行卡或收款账户信息 JSON 快照，适合保留申请提现时的账户信息。

## 10. 使用 RuoYi 代码生成器继续新增表

如果以后还要新增数据库表和对应功能，建议按下面流程做。

### 10.1 建表规范

新增业务表建议满足以下规范：

```sql
CREATE TABLE `xfpt_demo` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `del_flag` char(1) DEFAULT '0' COMMENT '删除标志（0代表存在 1代表删除）',
  `create_by` varchar(64) DEFAULT '' COMMENT '创建者',
  `create_time` datetime DEFAULT NULL COMMENT '创建时间',
  `update_by` varchar(64) DEFAULT '' COMMENT '更新者',
  `update_time` datetime DEFAULT NULL COMMENT '更新时间',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='示例业务表';
```

关键要求：

| 要求 | 说明 |
| --- | --- |
| 主键 | 推荐统一使用 `id bigint NOT NULL AUTO_INCREMENT` |
| 表名 | 建议以 `xfpt_` 开头 |
| 注释 | 表和字段都要写注释，代码生成器会读取 |
| 删除字段 | 建议使用 `del_flag` |
| 时间字段 | 建议使用 `create_time`、`update_time` |
| 备注字段 | 建议使用 `remark` |

## 19. 常见问题

### 19.1 前端页面报一堆乱码错误

常见原因：

1. 后端某个服务没启动。
2. 网关 `8080` 没启动。
3. Nacos 配置读取失败。
4. Redis 没启动，登录或验证码失败。
5. 后端返回中文异常，但编码被前端错误展示。

处理顺序：

1. 看 Nacos 服务列表是否有对应服务。
2. 看网关日志。
3. 看具体接口请求返回。
4. 检查 Redis 和 MySQL。

### 19.2 登录失败

检查：

```text
Redis 是否启动
Auth 服务是否启动
System 服务是否启动
Gateway 服务是否启动
Nacos 配置是否读取成功
数据库账号密码是否正确
```

### 19.3 新增功能菜单不显示

检查 SQL：

```sql
SELECT menu_id, menu_name, parent_id, menu_type, visible, status
FROM sys_menu
WHERE menu_name = '新增功能';

SELECT COUNT(*)
FROM sys_menu
WHERE parent_id = 2333
  AND menu_type = 'C';
```

正常应满足：

```text
新增功能 parent_id = 0
新增功能 menu_type = M
20 个页面菜单 parent_id = 2333
页面菜单 menu_type = C
visible = 0
status = 0
```

如果不是 admin 用户，还要检查角色菜单授权。

### 19.4 RuoYi 代码生成器导入表失败

检查：

1. `xfglpt-gen` 服务是否启动。
2. Nacos 中 `xfglpt-gen-dev.yml` 数据源是否指向 `xfglpt`。
3. MySQL 表是否有主键。
4. 表和字段是否有注释。
5. `gen_table`、`gen_table_column` 是否已有脏数据。

必要时清理某张表的生成器元数据后重新导入：

```sql
DELETE FROM gen_table_column
WHERE table_id IN (
  SELECT table_id FROM gen_table WHERE table_name = '你的表名'
);

DELETE FROM gen_table
WHERE table_name = '你的表名';
```

### 19.5 端口被占用

检查端口：

```powershell
netstat -ano | findstr ":8080"
netstat -ano | findstr ":9204"
netstat -ano | findstr ":9211"
netstat -ano | findstr ":80"
```

根据 PID 查看进程：

```powershell
tasklist | findstr "PID"
```

供应商模块固定使用 `9211`。如果 `9211` 被占用，需要先释放端口，不建议再改回 `9210`。

### 19.6 Nacos 启动失败

检查：

1. MySQL 是否启动。
2. `xfglpt-nacos` 是否导入成功。
3. `nacos\conf\application.properties` 中数据库密码是否正确。
4. `8848` 是否被占用。
5. JDK 是否是 JDK8。

### 19.7 后端启动报数据库连接失败

检查 Nacos 中每个服务配置：

```text
xfglpt-system-dev.yml
xfglpt-gen-dev.yml
xfglpt-job-dev.yml
xfglpt-school-dev.yml
xfglpt-app-dev.yml
xfglpt-supplier-dev.yml
```

重点看：

```yaml
url: jdbc:mysql://127.0.0.1:3306/xfglpt
username: root
password: 123456
```

### 19.8 前端 npm install 失败

建议：

1. 使用 Node 14 或 Node 16。
2. 删除 `node_modules` 和 `package-lock.json` 后重试。
3. 切换 npm 镜像。

示例：

```powershell
npm config set registry https://registry.npmmirror.com
npm install
```

### 19.9 前端打包有 warning

本机打包时有一些原项目遗留 warning，例如资源体积、部分导出缺失提示。只要没有 `ERROR`，一般不影响 `dist` 生成。后续如果要正式上线，应再单独清理这些 warning。
