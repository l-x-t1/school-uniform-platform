# 供应商端 23 表功能说明

本文档以 `sql/xfpt_supplier_23_tables.sql` 中的 23 张 `xfpt_*` 业务表为准，用于说明每张表在校服供应商端业务中的功能位置、上下游关系、关键状态和开发联调注意点。

不包含 RuoYi 自带的 `sys_*`、`gen_*`、`qrtz_*`、Nacos 配置表等基础框架表。SQL 文件里的 `gen_table` 和 `gen_table_column` 属于代码生成器元数据，不是校服业务表。

## 一、整体业务闭环

当前 23 表支撑的是一条完整链路：

学校发布统购公告 -> 供应商报名和比选 -> 学校与供应商形成合作关系 -> 供应商维护商品和尺码 -> 家长按统购或零售下单 -> 支付形成财务流水 -> 供应商生产和发货 -> 家长确认收货、评价或申请售后 -> 退款、结算、提现进入财务闭环。

核心主线如下：

1. 商品基础：`xfpt_goods`、`xfpt_goods_size`、`xfpt_goods_publish_log`
2. 学校合作与统购：`xfpt_group_notice`、`xfpt_group_notice_item`、`xfpt_supplier_apply`、`xfpt_school_supplier_rel`、`xfpt_school_supplier_goods_rel`
3. 家长购买辅助：`xfpt_student_size_ext`、`xfpt_user_address`、`xfpt_cart_item`
4. 订单履约：`xfpt_order_info`、`xfpt_order_item`、`xfpt_production_order`、`xfpt_production_order_item`、`xfpt_delivery_order`、`xfpt_delivery_order_item`
5. 售后评价：`xfpt_after_sale`、`xfpt_comment`
6. 财务结算：`xfpt_finance_flow`、`xfpt_settlement_order`、`xfpt_settlement_order_item`、`xfpt_withdraw_apply`

## 三、商品管理

### 1. `xfpt_goods` 商品信息

功能定位：供应商商品主表，用于维护校服商品的基础信息、图片、富文本详情、销售类型和上下架状态。

主要业务：

- 供应商新增、编辑商品。
- 商品可配置为统购、零售或统购零售都支持。
- 商品状态控制是否可用，上架状态控制是否对外展示和可购买。
- 下单、购物车、公告商品都会引用商品，并保存商品名称、主图等快照，避免后续商品改名影响历史单据。

关键字段：

- `goods_code`：商品编码，唯一。
- `supplier_id`、`supplier_name`：供应商归属及名称快照。
- `sale_type`：`1` 统购，`2` 零售，`3` 统购零售。
- `status`：`0` 草稿，`1` 启用，`2` 停用。
- `publish_status`：`0` 未上架，`1` 已上架，`2` 已下架。
- `main_image`、`detail_images_json`、`detail_content`：商品展示内容。

约束和索引：

- `uk_xfpt_goods_code` 保证商品编码唯一。
- `idx_xfpt_goods_supplier` 支持按供应商查询商品。
- `idx_xfpt_goods_status` 支持按启用和上架状态筛选。

对应接口和页面：

- 后端接口前缀：`/supplier/goods`
- 前端页面：`src/views/supplier/goods/index.vue`
- 前端 API：`src/api/supplier/goods.js`

### 2. `xfpt_goods_size` 商品尺码

功能定位：商品尺码和价格库存表，是商品下单和尺码推荐的基础表。

主要业务：

- 一个商品可配置多个尺码。
- 每个尺码可配置零售价、统购价、库存。
- `measure_json` 可保存量体规则，用于根据学生身高、体重、胸围等数据推荐尺码。

关键字段：

- `goods_id`：所属商品。
- `size_code`、`size_name`：尺码编码和名称。
- `gender_type`：`0` 通用，`1` 男，`2` 女。
- `retail_price`：零售价。
- `group_price`：统购价。
- `stock_num`：库存。
- `status`：`0` 停用，`1` 启用。

约束和索引：

- `uk_xfpt_goods_size_code` 保证同一商品下尺码编码唯一。
- `idx_xfpt_goods_size_goods` 支持按商品查尺码。
- `idx_xfpt_goods_size_status` 支持按状态筛选可用尺码。

对应接口和页面：

- 后端接口前缀：`/supplier/goodsSize`
- 前端页面：`src/views/supplier/goodsSize/index.vue`
- 前端 API：`src/api/supplier/goodsSize.js`

### 3. `xfpt_goods_publish_log` 商品上下架日志

功能定位：记录商品上架、下架操作日志，用于追踪商品对外售卖状态变化。

主要业务：

- 商品上架时插入一条上架日志。
- 商品下架时插入一条下架日志。
- 后续可用于审计、排查商品何时可售、谁操作。

关键字段：

- `goods_id`：商品 ID。
- `operate_type`：`1` 上架，`2` 下架。
- `operate_by`：操作人。
- `operate_time`：操作时间。

约束和索引：

- `idx_xfpt_goods_publish_log_goods` 支持按商品查看历史。
- `idx_xfpt_goods_publish_log_time` 支持按时间排序和审计查询。

对应接口和页面：

- 后端接口前缀：`/supplier/goodsPublishLog`
- 前端页面：`src/views/supplier/goodsPublishLog/index.vue`
- 前端 API：`src/api/supplier/goodsPublishLog.js`

## 四、统购报名与合作管理

### 4. `xfpt_group_notice` 统购公告

功能定位：学校统购业务的公告主表，承载选购公告和结果公告。

主要业务：

- 学校发布选购公告，指定年级、公告时间、报名开放状态。
- 供应商根据公告报名。
- 比选完成后可发布结果公告。
- 统购订单通过 `notice_id` 关联公告。

关键字段：

- `notice_code`：公告编号，唯一。
- `notice_type`：`1` 选购公告，`2` 结果公告。
- `status`：`0` 草稿，`1` 已发布，`2` 已结束，`3` 已撤回。
- `apply_status`：`0` 未开放，`1` 报名中，`2` 报名结束。
- `grade_ids`、`grade_names`：适用年级。
- `team_meeting_id`、`purchase_process_id`：关联学校采购流程资料。

约束和索引：

- `uk_xfpt_group_notice_code` 保证公告编号唯一。
- `idx_xfpt_group_notice_status` 支持学校维度按公告状态和报名状态查询。
- `idx_xfpt_group_notice_dept` 支持数据权限过滤。

对应接口和页面：

- 后端接口前缀：`/supplier/groupNotice`
- 前端页面：`src/views/supplier/groupNotice/index.vue`
- 前端 API：`src/api/supplier/groupNotice.js`

### 5. `xfpt_group_notice_item` 统购公告商品

功能定位：统购公告下的商品明细，说明本次统购涉及哪些商品、数量、价格说明和适用年级。

主要业务：

- 一个公告可配置多个商品。
- 每个商品可配置采购数量、尺码规则、价格说明和适用年级。
- 供应商报名和后续统购下单都应以公告商品范围为准。

关键字段：

- `notice_id`：公告 ID。
- `goods_id`、`goods_name`：商品 ID 和商品名称快照。
- `size_rule_json`：可选尺码规则 JSON。
- `buy_num`：采购数量。
- `price_desc`：价格区间或价格说明。
- `grade_ids`、`grade_names`：适用年级。

约束和索引：

- `uk_xfpt_group_notice_item_goods` 保证同一个公告下同一个商品只出现一次。
- `idx_xfpt_group_notice_item_notice` 支持按公告查询商品清单。
- `idx_xfpt_group_notice_item_goods` 支持从商品反查公告。

对应接口和页面：

- 后端接口前缀：`/supplier/groupNoticeItem`
- 前端页面：`src/views/supplier/groupNoticeItem/index.vue`
- 前端 API：`src/api/supplier/groupNoticeItem.js`

### 6. `xfpt_supplier_apply` 供应商报名

功能定位：供应商对统购公告的报名单，贯穿报名提交、资质审查、比选和中选结果。

主要业务：

- 供应商针对某个公告提交报名。
- 上传报名附件和比选资料。
- 学校或平台完成资质审查，给出通过或不通过。
- 比选完成后记录是否中选。
- 中选后通常会生成或更新学校供应商合作关系。

关键字段：

- `apply_no`：报名单号，唯一。
- `notice_id`、`school_id`、`supplier_id`：报名对应的公告、学校、供应商。
- `apply_status`：`0` 待提交，`1` 已提交，`2` 已撤回。
- `qualification_status`：`0` 待审查，`1` 通过，`2` 不通过。
- `bid_stage_status`：`0` 未进入，`1` 已进入，`2` 已完成。
- `bid_result_status`：`0` 未出结果，`1` 已中选，`2` 未中选。
- `apply_files_json`、`compare_files_json`：报名附件和比选资料。

约束和索引：

- `uk_xfpt_supplier_apply_no` 保证报名单号唯一。
- `uk_xfpt_supplier_apply_notice_supplier` 保证同一供应商对同一公告只能报名一次。
- `idx_xfpt_supplier_apply_status` 支持公告、供应商和审查/比选状态组合查询。

对应接口和页面：

- 后端接口前缀：`/supplier/supplierApply`
- 前端页面：`src/views/supplier/supplierApply/index.vue`
- 前端 API：`src/api/supplier/supplierApply.js`

### 7. `xfpt_school_supplier_rel` 学校供应商合作关系

功能定位：学校与供应商之间的合作主表，记录合作状态、合同、服务电话和合作周期。

主要业务：

- 供应商中选后形成合作关系。
- 合作期内供应商可为学校提供指定商品。
- 合作取消、历史合作也保留记录，便于追溯。
- 统购公告期内也可以通过状态标识临时合作关系。

关键字段：

- `school_id`、`school_name`：学校 ID 和名称快照。
- `supplier_id`、`supplier_name`：供应商 ID 和名称快照。
- `notice_id`：来源统购公告。
- `contract_id`：合同 ID。
- `cooperate_status`：`1` 合作中，`2` 已取消，`3` 历史合作，`4` 公告期内。
- `start_time`、`end_time`：合作周期。
- `service_phone`：供应商服务电话。

约束和索引：

- `idx_xfpt_school_supplier_rel_status` 支持按学校、供应商、合作状态查询。
- `idx_xfpt_school_supplier_rel_notice` 支持从公告反查合作关系。
- `idx_xfpt_school_supplier_rel_dept` 支持数据权限过滤。

对应接口和页面：

- 后端接口前缀：`/supplier/schoolSupplierRel`
- 前端页面：`src/views/supplier/schoolSupplierRel/index.vue`
- 前端 API：`src/api/supplier/schoolSupplierRel.js`

### 8. `xfpt_school_supplier_goods_rel` 学校供应商合作商品

功能定位：合作关系下的商品授权明细，说明某供应商可以给某学校供应哪些商品。

主要业务：

- 基于学校供应商合作关系绑定商品。
- 家长在学校范围内购买时，可按合作商品范围过滤可购商品。
- 合作商品可启用或停用。

关键字段：

- `rel_id`：合作关系主表 ID。
- `school_id`、`supplier_id`、`goods_id`：学校、供应商、商品。
- `status`：`0` 停用，`1` 启用。

约束和索引：

- `idx_xfpt_school_supplier_goods_rel_rel` 支持按合作关系查商品。
- `idx_xfpt_school_supplier_goods_rel_goods` 支持从商品反查合作范围。
- `idx_xfpt_school_supplier_goods_rel_dept` 支持数据权限过滤。

对应接口和页面：

- 后端接口前缀：`/supplier/schoolSupplierGoodsRel`
- 前端页面：`src/views/supplier/schoolSupplierGoodsRel/index.vue`
- 前端 API：`src/api/supplier/schoolSupplierGoodsRel.js`

## 五、家长购买辅助

### 9. `xfpt_student_size_ext` 学生尺码扩展

功能定位：学生量体和推荐尺码扩展表，用于提升家长选尺码准确性。

主要业务：

- 记录学生身高、体重、胸围、腰围、臀围。
- 根据商品尺码规则推荐尺码。
- 与学生保持一对一扩展关系，避免同一学生多条量体主记录。

关键字段：

- `student_id`：学生 ID。
- `height`、`weight`、`chest`、`waistline`、`hipline`：量体数据。
- `size_id`：推荐尺码 ID。
- `measure_time`：量体时间。
- `measure_remark`：量体备注。

约束和索引：

- `uk_xfpt_student_size_ext_student` 保证一个学生只有一条尺码扩展记录。
- `idx_xfpt_student_size_ext_size` 支持按推荐尺码统计或反查。

对应接口和页面：

- 后端接口前缀：`/supplier/studentSizeExt`
- 前端页面：`src/views/supplier/studentSizeExt/index.vue`
- 前端 API：`src/api/supplier/studentSizeExt.js`

### 10. `xfpt_user_address` 用户收货地址

功能定位：家长收货地址表，支持家庭地址和学校地址。

主要业务：

- 家长维护家庭收货地址。
- 学校统一收货时也可保存学校地址。
- 下单时订单会复制收货人、手机号和地址快照，避免地址后续修改影响历史订单。

关键字段：

- `user_id`：家长用户 ID。
- `receiver_name`、`receiver_phone`：收货人和手机号。
- `province_name`、`city_name`、`district_name`、`detail_address`：地址信息。
- `address_type`：`1` 家庭，`2` 学校。
- `is_default`：`0` 否，`1` 是。
- `status`：`0` 禁用，`1` 启用。

约束和索引：

- `idx_xfpt_user_address_user` 支持按用户查询地址簿。
- `idx_xfpt_user_address_status` 支持筛选启用地址。

对应接口和页面：

- 后端接口前缀：`/supplier/userAddress`
- 前端页面：`src/views/supplier/userAddress/index.vue`
- 前端 API：`src/api/supplier/userAddress.js`

### 11. `xfpt_cart_item` 购物车明细

功能定位：家长购物车表，暂存待购买商品、尺码、数量和价格快照。

主要业务：

- 家长加入商品到购物车。
- 支持统购商品和零售商品。
- 统购商品通过 `notice_id` 绑定统购公告。
- 生成订单时读取勾选的购物车明细，再写入订单主表和订单明细。

关键字段：

- `user_id`：家长用户 ID。
- `student_id`：学生 ID，统购或学生用品场景使用。
- `goods_id`、`size_id`：商品和尺码。
- `goods_name`、`size_name`、`main_image`：下单前展示快照。
- `unit_price`、`buy_num`：单价和数量。
- `checked_flag`：`0` 未选中，`1` 选中。

2. 供应商维护 `xfpt_goods_size` 商品尺码、价格和库存。
3. 商品上架时更新 `xfpt_goods.publish_status = 1`，并写入 `xfpt_goods_publish_log`。
4. 商品下架时更新 `xfpt_goods.publish_status = 2`，并写入 `xfpt_goods_publish_log`。

### 2. 统购报名和合作流程

1. 学校创建 `xfpt_group_notice` 统购公告。
2. 学校配置 `xfpt_group_notice_item` 公告商品。
3. 供应商创建 `xfpt_supplier_apply` 报名单并提交附件。
4. 学校进行资质审查，更新 `qualification_status`。
5. 比选完成后更新 `bid_stage_status` 和 `bid_result_status`。
6. 中选供应商生成 `xfpt_school_supplier_rel` 合作关系。
7. 合作关系下绑定 `xfpt_school_supplier_goods_rel` 合作商品。

### 3. 家长下单流程

1. 家长维护 `xfpt_user_address` 收货地址。
2. 系统或家长维护 `xfpt_student_size_ext` 学生尺码扩展。
3. 家长选择商品和尺码后写入 `xfpt_cart_item`。
4. 提交订单后生成 `xfpt_order_info` 和 `xfpt_order_item`。
5. 支付成功后更新订单支付状态，并写入 `xfpt_finance_flow` 支付流水。

### 4. 生产发货流程

1. 已支付订单生成 `xfpt_production_order`。
2. 订单商品拆入 `xfpt_production_order_item`。
3. 生产完成后更新生产单主表和明细状态。
4. 供应商生成 `xfpt_delivery_order`。
5. 商品发货明细写入 `xfpt_delivery_order_item`。
6. 发货后更新物流信息和发货状态。
7. 签收后更新发货单、发货明细和订单状态。

### 5. 售后流程

1. 家长基于订单明细创建 `xfpt_after_sale`。
2. 退换货、退款、尺码调换通过 `apply_type` 区分。
3. 尺码调换时必须填写 `target_size_id` 和 `target_size_name`。
4. 供应商或学校审核后更新 `status`、`audit_by`、`audit_time`。
5. 退款成功后写入 `xfpt_finance_flow` 退款流水。
6. 售后处理完毕后更新 `handle_result`、`handle_remark`、`finish_time`。

### 6. 评价流程

1. 订单完成后家长创建 `xfpt_comment`。
2. 同一用户对同一订单明细只能评价一次。
3. 供应商回复时更新 `reply_content` 和 `reply_time`。
4. 平台隐藏评价时更新 `status = 1`。

### 7. 结算提现流程

1. 支付和退款先进入 `xfpt_finance_flow`。
2. 平台按学校、供应商、周期生成 `xfpt_settlement_order`。
3. 订单收入、退款扣减、人工调整写入 `xfpt_settlement_order_item`。
4. 结算完成后可生成 `business_type = 3` 的结算财务流水。
5. 供应商提交 `xfpt_withdraw_apply`。
6. 提现打款后生成 `business_type = 4` 的提现财务流水，并回写 `finance_flow_id`。

## 十、接口和权限口径

23 张表当前均按 RuoYi CRUD 生成了 supplier 模块接口，网关访问路径以 `/supplier` 开头。每个业务对象的接口形态基本一致：

| 操作 | HTTP | 路径格式 | 权限格式 |
| --- | --- | --- | --- |
| 列表 | GET | `/supplier/{businessName}/list` | `supplier:{businessName}:list` |
| 详情 | GET | `/supplier/{businessName}/{id}` | `supplier:{businessName}:query` |
| 新增 | POST | `/supplier/{businessName}` | `supplier:{businessName}:add` |
| 修改 | PUT | `/supplier/{businessName}` | `supplier:{businessName}:edit` |
| 删除 | DELETE | `/supplier/{businessName}/{ids}` | `supplier:{businessName}:remove` |
| 导出 | POST | `/supplier/{businessName}/export` | `supplier:{businessName}:export` |

例如商品表：

- 列表：`GET /supplier/goods/list`
- 详情：`GET /supplier/goods/{id}`
- 新增：`POST /supplier/goods`
- 修改：`PUT /supplier/goods`
- 删除：`DELETE /supplier/goods/{ids}`
- 权限：`supplier:goods:list/query/add/edit/remove/export`

## 十一、开发联调注意点

1. 所有 `*_json` 字段只存 JSON 文本，不直接存文件二进制。图片或附件应先通过文件服务上传，再把 URL、文件名、说明等信息保存为 JSON。
2. 订单、售后、评价、发货、结算表大量使用快照字段，开发时不要只依赖当前商品或用户主数据，否则历史记录会被后续改名、改价影响。
3. `del_flag` 是逻辑删除字段，业务查询默认应过滤 `del_flag = '0'`。
4. 带 `dept_id`、`ancestors` 的表需要接入 RuoYi 数据权限，否则供应商、学校、平台角色可能看到不该看的数据。
5. 唯一约束字段应在接口层提前校验，避免数据库异常直接返回给前端。
6. 枚举字段必须以前端字典、后端校验、数据库注释三者一致为准。
7. 供应商端页面目前是按 RuoYi 生成器生成的基础 CRUD，复杂业务动作还需要继续补充专用按钮和后端服务方法，例如上架、下架、提交报名、审核、开始生产、确认发货、售后审核、结算申请、提现审核等。
